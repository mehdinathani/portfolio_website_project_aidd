2. **Embedding dimension mismatch.** `backend/src/services/gemini_service.py:20` uses `model="gemini-embedding-001"` which emits 3072-dim vectors. The live `knowledge_base.embedding` column is `vector(768)` (confirmed by parsing a sample row's `embedding` string field — 768 commas). Migration `012_update_knowledge_embedding_dim.sql` is the intended fix: it `DROP INDEX`, `ALTER COLUMN ... TYPE vector(3072) USING NULL`, recreates the HNSW index, and `CREATE OR REPLACE FUNCTION match_knowledge(vector(3072), ...)`. The `USING NULL` clause means **the 7 existing seed embeddings will be cleared** and must be regenerated by calling `gemini_service.generate_embedding(row.content)` for each row and `UPDATE knowledge_base SET embedding = ... WHERE id = ...`.
